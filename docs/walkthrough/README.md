# Product walkthrough video

Install the extension from the [Chrome Web Store](https://chromewebstore.google.com/detail/kokoro-reader/jjkkkegnnbehafabbhbolcdnfcjniamj).

`kokoro-reader-walkthrough.mp4` (1280×720, H.264/AAC, 3:11, 19 chapters with MP4 chapter markers and an English subtitle track; captions are also burned in). Chapter times are listed in [CHAPTERS.md](CHAPTERS.md); `kokoro-reader-walkthrough.srt` holds the subtitles.

## How it was made

Everything in the video is the real extension, recorded by `scripts/walkthrough/record.ts` and assembled by `scripts/walkthrough/compose.ts`:

1. **Narration** is generated by Kokoro Reader itself: each line is exported through the extension's WAV export with the female voice *Heart* (`af_heart`). No other speech engine is involved.
2. **Recording** runs the built extension in Chromium with a fresh profile, so the first-time model download and engine start are real. Pages are captured with the Chrome DevTools screencast, which timestamps every frame, and the composer always shows the tab that was in front.
3. **Reading audio.** Headless Chromium cannot capture its audio output, so for the two reading scenes the composer uses the extension's own Kokoro export of exactly the sentences that were read (same voice), each placed at the moment the extension started speaking it according to the recorded playback state.
4. **Composition** with FFmpeg: chapter badges and captions are rendered as transparent PNG overlays (this FFmpeg build has no `drawtext`), short fades between chapters, chapter metadata and a `mov_text` subtitle track. No background music is used.

Waits are real. The one exception is the model download in chapter 3, which took 44 s on the recording's connection: after the narration it plays at 4× with an on-screen label stating that and the real duration.

## Reproduce

```bash
npm run build:e2e && node scripts/walkthrough/record.ts && node scripts/walkthrough/compose.ts
```

`REUSE_NARRATION=1` skips regenerating the narration. Intermediate files go to `.cache/walkthrough/`.

The recording uses the end-to-end build, in which access to all sites is granted at install so the speaker button works without Chrome's permission prompt (automation cannot click it). In the release build the same toggle on the welcome page asks for that permission.
